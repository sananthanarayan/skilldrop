What a checkout request touches

What happens between a shopper pressing Pay and a courier being booked?

The API prices the cart from Redis (falling back to Postgres), charges Stripe, records the order and puts it on a RabbitMQ queue; a separate worker books the courier and marks the order booked. The shopper's response returns before the courier is booked.

Walkthrough

  1. The shopper's browser posts the cart to the Checkout API (the client itself is not in this repo).
  2. Each line is priced from Redis; a miss reads Postgres and caches the price for five minutes.
  3. Stripe is charged and confirmed in the same call; anything but 'succeeded' returns 402.
  4. The order is inserted, then its id is published to the fulfilment queue, and the API answers the shopper.
  5. Later, the worker takes the id, reads the address, books the courier and marks the order booked.

Notes

  • The worker reads orders.address, but the API's insert does not write an address. Where it comes from is not in this repo.
  • Left out: the products table's other readers, and anything after the courier booking.
